# Workshop Topics — one canonical, followable "what is this about?" layer

## Audit of the current branch

Confirmed by reading the code and querying the database:

- A canonical registry already exists: `public.topics` (id, slug, name, short_description, about_markdown, **aliases**, status, **merged_into_topic_id**, featured, created_by, timestamps) plus join tables `blog_post_topics`, `work_topics`, `group_topics`, `collab_post_topics`, `group_event_topics`, and `topic_follows` / `medium_follows`.
- Server layer exists at `src/lib/topics/topics.server.ts` (search, per-entity read, find-or-create, set-entity-topics, follows) with `src/lib/topics/topics.ts` for slugging/normalizing, plus `/topics`, `/topics/$slug`, `/mediums`, `follow-topic-button.tsx`, `topic-chips.tsx`.
- **Nothing is populated or wired**: `topics` has 0 rows, and all five join tables and `topic_follows` have 0 rows. No `TopicPicker` component exists; no authoring surface writes Topics today.
- Legacy storage is free-text arrays: `works.subjects` and `blog_posts.subjects`. Real legacy data is tiny — **1 Work** carries subjects (City, Comedy, Improvisation, Religion, Spirituality); **0 Blog posts** use them. Blog authoring/UI labels ("Subject/Subjects") live in `blog-editor.tsx`, `blog-about-editor.tsx`, `blog-filter-bar.tsx`, `blog-post-context.tsx`, `blog-form.ts`, `blog-filters.ts`; Work side in `work-form.ts`, `work-tags.ts`, `work-form-fields.tsx` (`SubjectField`), `work-about-section.tsx`, `work-card.tsx`, `works.new.tsx`, `works.$slug_.edit.tsx`.
- `pg_trgm` is already enabled, so fuzzy search is database-backed.
- Topics registry lacks: normalized comparison key + uniqueness, review state, family, broader/related relations, editorial order, old-slug redirects, seed data, and rate limiting.

Conclusion: reuse `public.topics` as the canonical registry (no competing table), keep join tables as the authoritative assignment store, and keep `*.subjects` arrays as read-only legacy fallback.

## Waves

### Wave 1 — canonical lifecycle + seeds (migrations)
- Add to `topics`: `normalized_key` (unique, generated by a shared SQL normalizer), `review_state` (reviewed | needs_review), `family`, `broader_topic_id`, `related_topic_ids`, `editorial_order`.
- New `topic_aliases` table (normalized alias unique across active topics) and `topic_slug_redirects` (old slug → surviving topic).
- Shared SQL + TS normalizer (NFKC, trim, lowercase, collapse whitespace, dash variants, drop terminal punctuation; no singularization). Uniqueness enforced in the DB so concurrent creates collapse to one record.
- Indexes: normalized key, alias trigram, slug, status/review, `topic_follows(user_id)`, `topic_follows(topic_id)`, join-table topic columns.
- RLS: anon may read active topics/aliases; only admins may edit labels, aliases, relations, featured/active/review/merge; members create only through a server function; `topic_follows` owner-scoped.
- Idempotent seed of the 100 Topics with families, scope descriptions, and the listed true aliases. Re-running never overwrites admin-edited descriptions.
- Grants for `anon` (read) / `authenticated` / `service_role` on every new table.

### Wave 2 — shared Topic picker + creation
- `src/lib/topics/search.server.ts`: ranked lookup (exact label → exact alias → label prefix → alias prefix → trigram similarity → usage tiebreak), paged, DB-side.
- `src/lib/topics.functions.ts`: `searchTopics`, `suggestTopics`, `createTopic` (auth required, 2–60 chars, moderation via `moderateOrThrow`, server-side re-check, race recovery returning the surviving row, 10 new topics / member / 24h via `rate_limits`), `setEntityTopics`.
- `src/components/topics/topic-picker.tsx`: chips + `+ Add a topic`, desktop popover / mobile sheet, exact copy from the spec, 6–8 contextual suggestions when empty, 8–12 results while typing, no create action on exact label/alias match, keyboard + screen-reader support, 44px targets, retired-topic handling.

### Wave 3 — Work and Blog parity
- Work: picker in `works.new.tsx` and `works.$slug_.edit.tsx` (max 5, optional), hydrate/save identically, chips on the Work page About block, at most one chip on `work-card`, tolerated by peeks/quick-create/gallery mappers.
- Blog: picker in member and admin editors (1–5 required to publish, drafts exempt, legacy posts editable without), included in validators, autosave deps, preview, select constants, public mappers, and About-this-post above Connections. First Topic acts as lead/primary focus on cards.
- All member-facing "Subject(s)" language becomes "Topic(s)".

### Wave 4 — Topic pages, follows, discovery
- Rebuild `/topics/$slug` with tabs (All / Blog / Gallery / Collabs / Groups / Events / Resources), hiding empty ones, paginated, permission-respecting (drafts, blocks, private groups, paused collabs, moderated content excluded).
- Follow/Following control, "Topics you follow" in Settings, Topic signal in For You / Following with de-duplication.
- URL-backed Topic filter in the existing `FilterHeader` on Gallery and Blog; Topics as a global-search result type; canonical URL + redirects + noindex for unused seeds.

### Wave 5 — Collabs, Groups, Events, Resources
- Collabs (max 3, create/edit/detail/filter, folded into existing terms-version behavior), Groups (max 5, admin + member edit, directory haystack), Events (up to 3 direct topics resolved at read time in union with inherited Group topics, provenance kept, deduped by ID, max 1–2 on cards), Resources (inherited Group topics + up to 3 direct where authoring supports it).

### Wave 6 — governance, migration, audit
- `/admin/topics`: search across labels/aliases/inactive, filters (reviewed, needs review, active, inactive, featured, seeded, member-created), usage counts per entity type, edit labels/aliases/relations/family, feature, activate/deactivate, and a single-transaction idempotent **merge** (rewrite every assignment table + follows with dedupe, source label becomes an alias, old slug redirect kept, source marked inactive/merged, never hard-deleted), logged through the existing admin audit conventions.
- Migrate the high-confidence legacy `works.subjects` / `blog_posts.subjects` values (exact and alias matches only) into join rows; leave ambiguous values untouched as legacy metadata. New data wins on reads; legacy renders only when no canonical rows exist, so nothing shows twice.
- Final sweep for stale "Subject" language, missing select fields, RLS, pagination, RSS, SEO, mobile, and accessibility.

## Technical notes

- Existing routes, slugs, Blog category URLs, Gallery behavior, Field/Category/Practice/Medium/Material/Form/Place/Skills, RLS, and moderation are untouched; every change is additive.
- No new applied migration is edited; each wave adds its own migration and regenerates Supabase types.
- Assignment join tables stay the single writable source of truth — no parallel `topic_ids` arrays.
- Typecheck, unit tests, and the acceptance checks in the request are run at the end of each wave before moving on.
